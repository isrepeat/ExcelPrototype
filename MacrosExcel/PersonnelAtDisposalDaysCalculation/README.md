# PersonnelAtDisposalDaysCalculation

Расчёт дней пребывания военнослужащих в распоряжении командира воинской части по событиям РУХ.

## Установка и текущий запуск

В книге `.xlsm` создайте стандартный VBA-модуль и вставьте содержимое `module_PersonnelAtDisposalDays.vba` без строки `Attribute VB_Name`. Выполните Debug → Compile VBAProject.

Назначьте существующим кнопкам:

- «Розрахувати» — `CalculateMovementDays`.
- «Скасувати» — `CancelMovementDays`.

`CalculateMovementDays` выполняет полный расчёт: читает I2/I3, открывает файл параметров только для чтения, читает диапазон C:F листа `Д3.Списки`, начиная со строки 3, сбрасывает фильтры открытого РУХ и записывает результат в `РозрахунокДнівРОЗП` на листе `Розрахунок днів РОЗП`.

Полностью пустые строки параметров пропускаются; частично заполненные проверяются как обычные строки. Уже открытую книгу параметров инструмент не закрывает. Книгу, открытую самим инструментом, закрывает без сохранения после успеха, ошибки или отмены. При открытии отключены обновление внешних ссылок и VBA-макросы; исходная настройка AutomationSecurity восстанавливается.

`DoEvents` обрабатывает отмену между этапами и в циклах. Одиночные вызовы Excel, включая открытие книги, синхронны. Повторный запуск защищён флагом.

## Конфигурация и таблицы

В начале модуля расположен блок `Configuration` с разделами `Source`, `Target`, `Parameters`, `Events`, `UI` и другими настройками. Имена колонок задаются отдельно для каждой таблицы. В заголовках используются одиночные пробелы.

Источник РУХ: лист `Відсутні`, таблица `ТВ`, колонки `ІПН`, `Подія`, `Вибуття`, `Прибуття`.

Целевая таблица `РозрахунокДнівРОЗП` на листе `Розрахунок днів РОЗП`:

| ПІБ | ІПН | Дата виведення у розпорядження | Кількість днів у розпорядженні | Періоди |
| --- | --- | --- | --- | --- |

В I2 укажите ссылку на файл, лист и первую ячейку заголовка умной таблицы:

```text
.\100.Д3.xlsx|Д3.Списки!B2
```

Поддерживаются абсолютные и относительные пути, адрес `$B$2`, имена листов с пробелами (также в апострофах). Относительный путь отсчитывается от папки книги инструмента. Все три части обязательны.

Код находит ListObject по первой ячейке заголовка и читает колонки по именам `ПІБ`, `ІПН`, `ВІДРЯДЖЕННЯ`, `ДЗС`. Названия настраиваются в PARAM_COL_*; порядок колонок и имя таблицы не важны. Обычный диапазон необходимо преобразовать в умную таблицу. Заголовки должны соответствовать конфигурации.

Пустое значение ВІДРЯДЖЕННЯ означает Ні: дни командировок вычитаются. ТАК означает засчитывать. Полностью пустые строки пропускаются, частично заполненные проверяются.

## Правила расчёта

Общая конечная дата читается из I3, индивидуальные даты — из внешней книги параметров.

Интервал `[начало, конец)`: конечная дата не включается, день прибытия засчитывается. Пустое прибытие означает открытое событие до конечной даты. Вычитаются `Стаціонарне лікування`, `Відпустка для лікування`, `ВЛК за межами`, а командировки — при выключенном флаге. Пересечения и дубликаты объединяются, разрывы учитываются как дни в наличии. Для примера 25.05.2026 → 31.08.2026 результат — 2 дня, 9 и 10 августа.

Результат записывается в шесть именованных колонок целевой таблицы. Ошибки проверки данных и отмена до записи сохраняют предыдущий результат. Перед чтением событий фильтры исходной умной таблицы РУХ сбрасываются через `AutoFilter.ShowAllData`; при ошибке операция прекращается с сообщением. Под таблицей результата оставляйте свободную область для расширения.

## Логирование и проверка

`ENABLE_LOGGING = True` включает ERROR/WARNING, дополнительный `ENABLE_DEBUG_LOGGING = True` — DEBUG. По умолчанию оба флага выключены. Лог расположен рядом с сохранённой книгой: `<имя книги>_logs.txt`. `ClearLog` очищает файл в начале текущего запуска чтения параметров. Ошибки записи сообщаются явно.

Сообщения пользователю — на английском; комментарии — на русском; имена колонок и событий сохранены на украинском. Встроенные функции вызываются через `VBA.`.

`TestMovementDays` проверяет алгоритм без изменения листов. Excel в среде разработки недоступен: компиляцию и запуск необходимо проверить в книге.

Типы событий настраиваются списками через `|`: `EXCLUDED_EVENTS` — всегда исключаемые, `OPTIONAL_EXCLUDED_EVENTS` — исключаемые при выключенном флаге `Враховувати відрядження`. Для добавления типа достаточно изменить соответствующий список. Сравнение полных названий без учёта регистра, как в `module_PeriodsGeneration`.

Относительная часть пути в I2 разрешается относительно папки сохранённой книги инструмента.

Строки РУХ без ІПН (включая ошибки в ячейке идентификатора) пропускаются. События и даты проверяются только после совпадения ІПН со списком людей в параметрах. ІПН в самой таблице параметров остаётся обязательным.

Добавьте в целевую умную таблицу колонку `Періоди`. Она содержит зачтённые интервалы по хронологии через ` | `; обе показанные даты включаются в интервал. Пример: `09.08.2026–10.08.2026`. Для одного дня начало и конец совпадают; при нуле зачтённых дней ячейка пустая. Общая конечная дата I3 по-прежнему не включается. Текст и количество дней вычисляются из одних и тех же интервалов.

Периоды подписываются названиями событий из РУХ: `В строю (09.08.2026–10.08.2026) | Щорічна відпустка (...)`. `В строю` используется только для промежутков без событий. Смена типа разделяет периоды. При пересечении зачтённых событий показываются все уникальные названия через ` / `, дни считаются один раз. Исключаемое событие перекрывает зачтённое. Даты теперь проверяются для всех типов событий выбранных людей, поскольку они нужны для подписей.

Если событий нет, наличие человека подтверждается в таблице `Список` на листе `Список` той же книги РУХ. Только после подтверждения весь интервал считается `В строю`.

Поиск выполняется сначала по ІПН во всех событиях, и только при отсутствии совпадений — по полному ПІБ без учёта регистра. Если событий нет, такой же поиск выполняется в `Список`; найденный там ІПН используется для повторной проверки событий. Сокращение в поле ІПН (например `ДРАЙ В.В.`) не используется как ФИО: берётся полное имя из колонки ПІБ параметров. При нескольких разных ІПН для одного имени или отсутствии человека в обоих источниках он выводится ниже результата с конкретной ошибкой. Фильтры Списка не влияют на чтение; поля `В строю`, `Зарахування`, `Виключення` не изменяют заданный пользователем интервал.

Поиск ускорен однократным построением индексов ІПН и ПІБ для событий и Списка. Повторного обхода всех строк для каждого человека нет. Проверки отмены сохранены; обновления UI в циклах ограничены интервалом 0,1 секунды.

Колонка результата `Враховувати відрядження` получает исходное значение из `PARAM_COL_TRIPS` без преобразования (ТАК, TRUE, число или пустая ячейка). В новой разметке ссылка вводится в I2, конечная дата — в I3.
