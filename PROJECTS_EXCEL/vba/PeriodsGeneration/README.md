# PeriodsGeneration

Режим генерации непрерывных периодов в архитектуре PROJECTS_EXCEL.

## Структура

- `ex_PG` — инициализация режима и открытие страницы.
- `obj_PG_PgMain` — реализация `obj_IPage`, жизненный цикл страницы.
- `obj_PG_PgMainController` — привязки формы, результата и команд расчёта, отмены и обновления.
- `obj_PG_Configuration` — проверка и загрузка обязательных значений wsConfig.
- `obj_PG_Parameters` — чтение начальной и конечной дат из Form.
- `obj_PG_DataSource` — поиск единственной открытой книги РУХ и проверка колонок.
- `obj_PG_RunContext` — отмена, проверка остановки при перезагрузке и диагностика.
- `obj_PG_CalculationRun` — создание сервисов на каждый запуск и освобождение ресурсов.
- `obj_PG_Period` — объект события или объединённого периода.
- `obj_PG_CalculationService` — чтение событий, сортировка, объединение и фильтрация, подготовка результата в памяти.
- `obj_PG_ResultWriter` — публикация через Data.CalculationRows и перерисовка страницы.
- `ThisWorkbook` — события книги с защитой общего runtime.

Разметка: `PROJECTS_EXCEL/ui/PeriodsGeneration/MainPage.xaml`.
Конфигурация: `PROJECTS_EXCEL/config/PeriodsGeneration/wsConfig.txt`.
Книги: `PROJECTS_EXCEL/workbook/PeriodsGeneration`.

## Работа

Откройте одну книгу-источник с настроенными листом и таблицей (по умолчанию Відсутні / ТВ), заполните начальную и конечную даты на странице и нажмите кнопку расчёта. Форма принимает Excel-даты и текст dd.mm.yyyy. Начальные значения дат пустые, ввод обязателен.

Результат содержит десять колонок исходного модуля. Имена колонок, события для объединения и отображения, подписи, сообщения и формат дат заданы в wsConfig. Значения конфигурации обязательны; скрытые значения по умолчанию не используются.

Сохранена семантика исходного алгоритма: группировка по ІПН, сортировка по датам, объединение пересекающихся периодов или общей граничной даты только для разрешённых событий, фильтрация по пересечению с диапазоном без обрезки исходных дат. Объединение соседних календарных дней остаётся отключённым. Для открытых периодов количество дней считается до даты запуска, без прибавления единицы. Некорректные события и строки без ІПН пропускаются с диагностикой, как в исходном модуле. Фильтры источника не изменяются; чтение Value2 включает скрытые строки.

Результат строится в памяти и публикуется после проверки отмены. Старые целевой лист, ListObject и параметры D3/E3 больше не нужны. Обновление страницы блокируется во время расчёта.

## Подключение

Профиль `PeriodsGeneration` зарегистрирован в `PROJECTS_EXCEL/vba/modules.json` и включает только общий движок и исходники этого режима. Общие фабрика страниц и механизм перезагрузки вызывают функции из обязательных ключей `ThisWorkbook::pageFactory` и `ThisWorkbook::initializer`. В конфигурации этого режима они указывают на `ex_PG.fn_CreatePage` и `ex_PG.fn_Initialize`. Конкретная страница создаётся в модуле режима.

Для подготовки книги необходимо создать лист MainPage (его имя соответствует MainPage.xaml), явно загрузить строки wsConfig в лист wsConfig / таблицу tbConfig и импортировать профиль PeriodsGeneration через `Scripts/PowerShell/Update-WorkbookModules.ps1` с `-VbaFolderPath PROJECTS_EXCEL/vba -Profile PeriodsGeneration`. Для проверки плана импорта без Excel добавьте `-PlanOnly`.

Изменение исходников само по себе не обновляет книгу. Импорт, компиляция и выполнение VBA требуют отдельного явного запроса.
