`table` и `tableList` используют `obj_UiRawTable` / `obj_IUiTableSource`; идентификатор данных не требуется. По умолчанию Raw записывает один двумерный буфер через `Range.Value2`. Smart создаёт Excel `ListObject` поверх заголовков и данных до запуска штатного конвейера стилей. Название раздела остаётся вне ListObject.

## XAML

Политики таблиц задаются явно в XAML. Элементы политики, включая обёртку свойства, используют namespace controls; стандартные page/grid — namespace profiles.

```xml
<controls:tableList name="Results"
                    itemsSource="{Binding Source=Data; Path=Tables}">
    <controls:tableList.tablePolicy>
        <controls:tablePolicy defaultRepresentation="Raw">
            <controls:rule index="2"
                           representation="Smart"
                           excelTableName="tbSummary" />
            <controls:rule index="5, 8-12"
                           representation="Smart" />
            <controls:rule index="10"
                           representation="Raw" />
        </controls:tablePolicy>
    </controls:tableList.tablePolicy>
</controls:tableList>
```

Индексы начинаются с единицы и относятся к одному TableList. Запятые разделяют позиции или включительные возрастающие диапазоны. Допускаются только положительные десятичные целые до 2147483647. Отсутствующая позиция ничего не выбирает. Правила выполняются по порядку: позднее совпадение меняет представление и указанное имя; Raw сбрасывает унаследованное имя. Правила разбираются при настройке контрола, диапазоны хранятся интервалами, без разворачивания в массивы.

`excelTableName` требует Smart и ровно одну позицию; интервал `2-2` также допустим. Одно фиксированное имя нельзя назначить нескольким таблицам Excel. Атрибут TableList `representation="Raw|Smart"` задаёт значение по умолчанию, которое переопределяется вложенным `defaultRepresentation`.

Одиночная таблица:

```xml
<controls:table name="Summary"
                itemsSource="{Binding Source=Data; Path=Summary}"
                representation="Smart"
                excelTableName="tbSummary" />
```

Явное имя содержит ASCII-буквы, цифры и подчёркивания, начинается с буквы или подчёркивания, имеет длину до 255 символов и не должно напоминать адрес ячейки. Конфликт имени в книге вызывает ошибку. Автоматическое имя имеет вид `tbGenerated_<sheet>_<control>_<index>_<hash>`: части очищаются и обрезаются, числовой суффикс устраняет коллизии. Хеш различает совпавшие после очистки имена и списки разных листов. Это имена мест представления, а не записей или бизнес-сущностей.

## Преобразование уже выведенной таблицы

```vba
Dim context As obj_UiRenderContext
Dim diagnostic As String

If Not ex_UiRuntime.fn_TryGetContext(ActiveSheet, context) Then Exit Sub
If Not context.TryEnsureSmart("Results", 2, diagnostic, "tbSummary") Then
    MsgBox diagnostic, vbExclamation
    Exit Sub
End If
```

Для автоматического имени опустите последний аргумент. Повторный вызов использует принадлежащий UI ListObject; без аргумента имени сохраняет существующее. Преобразование берёт сохранённые границы заголовка и тела, не переписывая значения. Нужна успешно выведенная таблица с видимыми заголовками и хотя бы одной строкой. Изменение касается текущего представления; следующая полная отрисовка снова применит XAML. Между отрисовкой и позиционным вызовом нельзя вручную перемещать результат, вставлять или удалять строки листа.

Вне готовой страницы используйте `ex_UiTables.fn_TryEnsureSmart(range, owner, diagnostic, optionalName)` с явным непрерывным диапазоном заголовка и тела. owner — локальный ключ представления листа, например `Results|2`, а не обязательный ID модели. Выделяйте отдельный лист вывода: полная отрисовка UI владеет его управляемыми таблицами и удаляет отсутствующие в новом плане.

## Жизненный цикл и поведение

- Планы формируются при раскладке и до изменения объектов проверяются на владение, повтор имён и пересечения.
- Скрытые имена книги с префиксом `_pxTable_` фиксируют владение. Ключ включает CodeName листа; комментарий хранит имя ListObject. Маркеры сохраняются в книге, переживают Dispose контекста и сброс VBA. Редактировать их вручную нельзя.
- Таблица на той же позиции заголовка используется повторно и меняет размер; при сжатии лишние ячейки очищаются. Перемещённая таблица преобразуется в диапазон и создаётся заново: внешние структурированные ссылки могут не сохраниться. Для постоянных формул используйте фиксированные позиции.
- Удаление таблицы или переход Smart → Raw снимает принадлежащий UI ListObject, затем записывает актуальные Raw-данные. Чужие ListObject не присваиваются по имени; пересечение с очисткой или записью UI вызывает ошибку.
- Полная отрисовка сбрасывает фильтры и заново записывает источник. Пользовательская сортировка не меняет порядок массива. Smart запрещает `onSelect` / `selectedItem`: текущая модель выбора зависит от физического порядка строк.
- Smart требует уникальные непустые текстовые заголовки до 255 символов и `showHeaders="true"`. Пустой источник резервирует одну пустую строку тела, но сообщает ноль записей. Пустую Raw-таблицу нельзя повысить до Smart позиционным API без новой раскладки.
- Встроенный TableStyle очищается; оформление задаёт конвейер стилей. Объединение ячеек внутри Smart Excel не поддерживает.
- Прямое преобразование восстанавливает прежние ScreenUpdating и EnableEvents и при успехе, и при ошибке. Полная страница использует свою защиту. Отрисовка и преобразование временно отключают AutoExpandListRange и AutoFillFormulasInLists с восстановлением. Режим вычислений не меняется.

## Проверка

`WorkbookUpdater/Test-UiElements.ps1` содержит запускаемые по разрешению Excel-проверки селекторов, приоритетов, смешанного вывода, явных/автоматических имён, границ названий, повторной отрисовки, позиционного преобразования, изменения размеров, пересоздания контекста, удаления старых таблиц и конфликтов имён/заголовков. Скрипт запускает Excel и VBA; требуется явное разрешение. Проверки XML и исходников не подтверждают runtime-корректность. Новые классы и модули подхватываются масками `modules.json`.
