## Назначение

Страница владеет скомпилированным `obj_UiStylePipeline`. `BeginPage` читает общие и локальные именованные стили, один раз компилируя селекторы и объявления. Для каждого контрола XML не сериализуется и объявления заново не разбираются. `BeginRender(rows, columns)` очищает runtime-области и до отрисовки контролов применяет включённые правила `target="sheet"` стадии `default`. Область включает измеренную страницу, используемый диапазон и минимальный охват листа. Полная отрисовка регистрирует новую геометрию; `CompleteRender` применяет остальные правила default. Именованные стадии можно вызвать через `Styles.ApplyStage`.

Правила выполняются в XML-порядке слоёв в пределах фазы: сначала default для листа, затем именованные стили и прямые атрибуты контролов, после — остальные default-правила. `enabled=false` на стадии, слое или правиле отключает соответствующие правила. Поэтому листовые правила не требуют повторного применения собственных стилей контролов. Поздние объявления переопределяют оформление; выделение выбранной строки восстанавливается последним. Явные вызовы `ApplyStage` сохраняют XML-порядок для всех целей.

Поддерживаемые цели: `sheet`, `usedRange`, `row`, `column`, `cell`, `range`, `control`, `controlPart`, `layoutContainer`, `layoutBound`, `inlinePart`. Диапазон выбирается через `row=2:8`, `col=3:5` или `address=B2:D8`. Для ячейки нужны row/col либо address; для диапазона — address. Runtime-селекторы принимают type, name, style, tags, element, elementDepth, part. Фильтр листа необязателен. Неизвестные ключи, некорректные объявления, повторные ключи и неверный enabled останавливают инициализацию.

Перед визуальным форматированием целые строки и колонки обрезаются по области страницы; структурная ширина по-прежнему задаётся всей колонке листа. Правило address=A:A поэтому не заполняет миллион ячеек. Повторная регистрация той же runtime-области заменяет прежнюю, не накапливая дубли. Полосатое оформление объединяет до 64 строк в одну операцию Excel.

Grid и stackPanel регистрируют границы раскладки. Контролы — области control/cell/shape. Table и tableList — название section, header и rows. Дочерние таблицы TableList сохраняют тип и имя владельца для селекторов. Алиасы колонок header/data сейчас равны отображаемому заголовку. `RegisterPart` также принимает columnAlias, sourceAlias и sourceAliasTemplate, если поставщик располагает этими данными. Алиас — точное совпадение с зарегистрированной областью, а не адрес листа.

```xml
<stylePipelineStage name="default">
  <layer name="table-formatting">
    <rule target="controlPart"
          selector="type=table;part=header"
          styles="{backColor:#355D8C;fontColor:#FFFFFF;fontBold:true;}"/>
    <rule target="controlPart"
          selector="type=table;part=rows"
          styles="{backColor:#2D2D2D;fontColor:#FFFFFF;}"/>
    <rule target="controlPart"
          selector="type=table;part=row;tags=even"
          styles="{backColor:#383838;}"/>
  </layer>
</stylePipelineStage>
```

Таблица регистрирует каждую строку данных как `part=row` с метками `tableRow odd` или `tableRow even`. Нумерация начинается с единицы, исключает заголовок и название и начинается заново для каждой таблицы в tableList. Область всего тела сохраняет `part=rows`. Движок стилей не вычисляет чётность: он выбирает области по меткам.

`tags=even` требует метку even; `tags=tableRow even` — обе метки. Сравнение без учёта регистра, по целым словам, разделённым пробелами. Метки области дополняют `tags` элемента. Необязательный параметр `tags` в `RegisterPart` позволяет другим контролам регистрировать смысловые метки.

`element=stackPanel` выбирает элемент разметки; `elementDepth=0` или `elementDepth=3:10` — глубину либо диапазон глубин среди родителей XML. Старые `tag` и `tagDepth` не поддерживаются. Селектор `parity` заменён метками строк.

Объявления поддерживают цвета, шрифты, границы, горизонтальное/вертикальное выравнивание, overflow, width/columnWidth, minWidth/maxWidth, autoFitColumns, rowHeight (число или auto), cellType (text/date/general), масштаб и gridLines. Ширина измеряется в Excel ColumnWidth и меняет колонки, общие для соседних контролов. Структурные свойства обычно задаются правилами range/column.

`ResolveInlineStyle` возвращает объединённые объявления для текстового обработчика; обычная ячейка не становится rich text автоматически. Алиасы источников и области itemBanner/rowBanner должны регистрироваться контролом, понимающим данные. В PROJECTS_EXCEL пока нет вывода banner-строк и rich-text таблиц, поэтому соответствующие обработчики PrototypeNew не перенесены. Поддерживается полная отрисовка страницы; частичное повторное применение стилей и смещение границ PrototypeNew для этой политики не требуются.

`WorkbookUpdater/Test-StylePipelineSources.py` и `WorkbookUpdater/Test-LookupSources.py` проверяют объявления и конфигурацию без изменений файлов. Они не подтверждают runtime-поведение VBA; компиляция, импорт и макросы требуют отдельного разрешения.
