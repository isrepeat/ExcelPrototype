# History-to-Word performance

Each export rebuilds the complete selected order from the empty template. After insertion and verification, all Begin/End export markers, including unused section markers, are deleted from the generated document before saving. Paragraphs and other content are preserved, and removal is verified against the expected document text. The source template remains unchanged. Publishing still checks that an existing output file has not changed and replaces it atomically. No partial document update or cross-export result cache is introduced.

History event preparation no longer renders section bodies. The exporter renders each text-only event once, or each grouped section once after collecting its members. Text-only parts are assembled with Join. The batch shares one initialized XML template catalog with the preparation service; the service owns only catalogs it creates itself. Document replacements and output filename are prepared from the first included event and reused only after comparing the configured common fields for all later included events.

export.Word.documentContext.fields declares inputs shared by document-level expressions. Both profiles currently declare AcceptedOrderNumber, AcceptedOrderDate and Signatory, covering all six configured replacement expressions. If a document-level expression gains another input, add that input to this contract so differing values are rejected rather than silently reused.

## Timings

diagnostic.log contains Word.Export.* PERF entries. ReadEvents measures history loading; PrepareJournal measures event journal preparation. Prepare.Initialize, Prepare.Events and Prepare.RenderSections cover in-memory preparation. AcquireWord measures process creation or reuse separately from CreateDocument. ReplaceDocumentFields and Section.IndexAnchors run once per document; Insert and Verify run per populated section. SaveDocument, CloseDocument and PublishDocument cover file work. RecordJournal and RefreshHistory cover post-generation history updates. GenerateTotal includes generation cleanup; TotalIncludingJournalAndRefresh covers the command through the final status refresh, before its final diagnostic flush.

WORD_EXPORT_BATCH records event and populated-section counts. Per-section totals include the event type in the stage name. Repeated stage names are separate samples and must be summed within one command. Measurements use the existing diagnostic timer; no estimated timings are presented as actual results.

## Manual benchmark

Cleanup now plans removals from one text snapshot, merges adjacent spans and resolves all Word ranges before mutation. A single marker search calibrates string offsets against Word positions; each candidate range must match its planned text. If fields or objects change the mapping, cleanup locates both marker boundaries for that span and verifies it again. Verified ranges are deleted in reverse order, then the full result is compared with the independently constructed expected text. No complete-document text replacement is used, preserving styles, fields and numbering.

`Word.Export.Cleanup.Plan`, `Cleanup.ResolveRanges` and `Cleanup.DeleteRanges` split the work. `WORD_CLEANUP_PLAN` reports merged range and fallback counts. `Test/ex_PEB_WordCleanupTests.vba` supplies explicit, manually invoked Word regression cases for empty/populated/mixed blocks, separator paragraphs, legacy anchors and field-dependent character offsets. These macro tests must not run automatically; static validation alone does not establish correctness or speed in Word.

Use disposable copies of the output and history books. Compare 1, 10, 50 and 100 active events, first in one section and then distributed across sections. Record the first export after page initialization and an immediate repeated export separately. Retain event counts, section counts, total output characters/pages and the stage timings. A first Word launch and reuse are distinct cases; do not restart or close a user's unrelated Word process for measurements.

The 2026-10-24 13:22:54 live-history export took 28.3 seconds: eight repeated block indexes consumed about 13.7 seconds, and final cleanup consumed 7.0 seconds before verification failed. The block index now validates paragraph boundaries against the captured text in memory and is reused for all insertions and final cleanup. Cleanup computes string offsets from uniquely identified removed text, rather than treating Word character positions as string offsets. Full-document verification remains enabled; WORD_CLEANUP_MISMATCH records expected/actual lengths and the first differing offset without document contents. Runtime Word formatting behavior and throughput still require interactive verification; static contracts cannot prove them.
