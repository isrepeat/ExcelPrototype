API читает внешние таблицы Excel независимо от UI. Компоненты включены существующими масками `vba/modules.json`. Для использования в книге нужно импортировать или перезагрузить исходники; сами отслеживаемые книги этим изменением не обновляются.

## Использование

```vba
Dim source As New obj_TableSource
Dim query As New obj_TableQuery
Dim service As New obj_TableQueryService
Dim result As obj_DataTable
Dim diagnostic As String

If Not source.Initialize() Then Exit Sub
If Not query.Initialize() Then Exit Sub
If Not service.Initialize() Then Exit Sub

source.WorkbookPath = "C:\Data\Personnel.xlsx"
source.TableName = "tblPersonnel"
query.AddColumn "ID"
query.AddColumn "Name"
query.AddCondition "Amount", QueryGreaterOrEqual, 10, QueryNumber
query.AddOrderBy "Amount", True, QueryNumber
query.AddOrderBy "ID", False, QueryNumber
query.Limit = 20

If Not service.TryExecute(source, query, result, diagnostic) Then
    MsgBox diagnostic, vbExclamation
    service.Dispose
    Exit Sub
End If

' Успешный запрос может вернуть ноль строк, сохранив заголовки.
Debug.Print result.RowCount
service.Dispose
```

Для обычного диапазона не задавайте `TableName`, а укажите `SheetName` и `RangeAddress`, например `A1:F500`. `RangeAddress="auto"` определяет диапазон от A1 до последней заполненной строки и последнего заголовка первой строки, учитывает новые записи и игнорирует ячейки, занятые только форматированием. Требуются заголовки в строке 1. Оба механизма используют одинаковый путь получения метаданных сессии. Диапазон должен быть непрерывным; заголовки — непустыми и уникальными после обрезки пробелов и сравнения без регистра. У ListObject заголовок должен быть видимым; строка итогов исключается. Читаются все строки, включая скрытые фильтрами.

## Контракты

| Компонент | Ответственность |
| --- | --- |
| `obj_TableSource` | Путь книги и имя ListObject либо явный диапазон. |
| `obj_TableQuery` | Проекция, дерево фильтров, упорядоченные ключи сортировки, лимит. |
| `obj_QueryCondition` | Типизированное сравнение и независимые текстовые параметры. |
| `obj_QueryGroup` | AND по умолчанию, OR при `MatchAny=True`, вложенные группы. |
| `obj_QueryOrder` | Колонка, тип, направление, текстовые параметры. |
| `obj_DataTable` | Заголовки с нулевого индекса, двумерные значения с единицы, размеры. |
| `obj_ITableQueryExecutor` | Только `TryExecute`; жизненным циклом управляет конкретный исполнитель. |
| `obj_ExcelQueryExecutor` | Живые данные или объектная модель Excel только для чтения. |
| `obj_AdoQueryExecutor` | Сохранённый файл через ACE OLE DB. |
| `obj_TableQueryService` | Выбор механизма и освобождение ресурсов. |

Пустой список колонок означает выбор всех. `Limit=0` снимает ограничение, отрицательное значение недопустимо. Сортировка стабильная и предшествует лимиту. Для однозначного выбора среди равных значений добавьте уникальный последний ключ. ADO без явной сортировки не гарантирует физический порядок строк.

Операторы: `QueryEquals`, `QueryNotEquals`, `QueryContains`, `QueryStartsWith`, `QueryEndsWith`, `QueryIsEmpty`, `QueryIsNotEmpty`, `QueryGreater`, `QueryGreaterOrEqual`, `QueryLess`, `QueryLessOrEqual`. Поиск подстроки, начала и окончания считает `%`, `_`, `[` и прочие символы буквальными.

Типы задаются явно: `QueryText`, `QueryNumber`, `QueryDate`, `QueryBoolean`. Для строковых чисел и дат действуют явные форматы из раздела ниже; не полагайтесь на локаль VBA. Даты принимаются как VBA Date и числовые даты Excel с указанной системой. Вместо неоднозначных строк используйте `DateSerial`. Проекция сохраняет тип читателя: ADO может вернуть Date там, где Excel Value2 возвращает Double.

`NormalizeText=True` заменяет NBSP пробелом, удаляет CR/LF/табуляцию и обрезает внешние пробелы, не меняя чувствительность к регистру. `CaseSensitive=False` по умолчанию использует текстовое сравнение VBA. Null, Empty и пустая строка считаются пустыми; строка из пробелов — только при нормализации. Пустые значения не проходят обычные сравнения, включая неравенство: используйте явные проверки пустоты. Excel-ошибки в колонке фильтра или сортировки завершают запрос с диагностикой. Пустые значения идут первыми по возрастанию и последними по убыванию.

Для OR создайте `obj_QueryGroup`, задайте `MatchAny=True`, добавьте условия и вызовите `query.Filter.AddGroup group`. Пустая AND-группа подходит всем строкам, пустая OR — ни одной. Циклические ссылки отклоняются. API синхронный; менять запрос во время исполнения нельзя.

## Механизмы чтения и ресурсы

`service.Backend=QueryAuto` читает книгу, открытую в текущем Excel Application, через Excel-исполнитель, включая несохранённые данные. Иначе выбирается ADO. Относительные пути считаются от текущего рабочего каталога; рекомендуется абсолютный путь.

`QueryExcel` открывает закрытый источник только для чтения в собственном скрытом Excel, отключая макросы, события и обновление ссылок. Закрываются только собственные книги. Пользовательские книги не сохраняются и не закрываются. `QueryAdo` читает сохранённый файл, даже если текущий Excel содержит несохранённую копию. Открытая в другом экземпляре Excel книга не считается живой для Auto.

Текущий ADO-исполнитель получает метаданные таблицы/диапазона через временный Excel только для чтения, закрывает его, затем читает ACE SQL только выходные колонки и колонки фильтра/сортировки. Оба механизма применяют дерево условий, стабильную сортировку и лимит одним обработчиком в памяти. Переноса WHERE/ORDER BY/TOP в SQL пока нет: загружаются все строки нужных колонок. Это сохраняет единые правила сравнения, но увеличивает память и время передачи больших источников. Кеша соединений или результатов нет; каждый запрос освобождает ресурсы.

ADO требует установленный провайдер `Microsoft.ACE.OLEDB.12.0` подходящей разрядности; поддерживаются `.xls`, `.xlsx`, `.xlsm`, `.xlsb`. Вывод типов ACE может изменить данные или потерять смешанные значения и длинный текст ещё до общего обработчика. Для точных Excel-значений явно выбирайте `QueryExcel`. После ошибки ADO нет молчаливого переключения. Книги с паролем и интерактивный ввод учётных данных не входят в API.

`TryExecute=False` возвращает `Nothing` и описание ошибки: вызывающий код должен показать диагностику и остановиться. Успех с нулём строк допустим. `result.TryCreateUiTable` преобразует результат в `obj_UiRawTable`, включая пустой; исполнение запроса не зависит от контроллеров и привязок страницы.

## Явные форматы чисел и дат

`QueryText` не меняется. Типизированные числа и VBA Date не требуют текстового формата. Числовые и календарные строки требуют инициализированный `obj_QueryValueFormat`; без него строка отклоняется, а не трактуется по локали компьютера. Условия и сортировка используют одинаковые преобразования `ex_TableQuery.fn_NumberValue` / `fn_DateValue`.

Вызовите `Initialize(decimalSeparator, groupSeparator, dateFormat, dateSystem)` и проверьте Boolean-результат. Десятичный разделитель — `.` или `,`; необязательный разделитель тысяч — `.`, `,`, пробел или NBSP, отличный от десятичного. После первой группы каждая содержит три цифры. Разрешены начальный знак и дробная часть; валюта, экспонента и другой синтаксис запрещены. Форматы даты — только `dd.MM.yyyy` и `yyyy-MM-dd`. После DateSerial компоненты перепроверяются, невозможные даты отклоняются.

Форматы приложения задаются в `wsConfig` / `tbConfig`. Для `format.InitializeFromConfig(prefix)` нужны четыре ключа: `<prefix>.decimalSeparator`, `.groupSeparator`, `.dateFormat`, `.dateSystem`. Неиспользуемое значение — `none`; разделитель групп также принимает `space`, `nbsp`. Недостающий ключ или неверная настройка срывает инициализацию; вызывающий код должен сообщить ошибку и остановиться. Форматы не выводятся из локали Windows.

`query.AddCondition` принимает последние необязательные объекты `sourceFormat` и `valueFormat`, независимо описывающие колонку и значение условия. У прямого условия доступны `SourceFormat` и `ValueFormat`. `query.AddOrderBy` принимает последний `valueFormat`, доступный также в `obj_QueryOrder`. Объекты формата заимствуются и должны оставаться инициализированными до конца обработки. Dispose условия или сортировки освобождает ссылки, но не общий формат.

Пример сравнения явно форматированной колонки даты с типизированной датой: `query.AddCondition "When", QueryGreaterOrEqual, DateSerial(2026, 4, 3), QueryDate, False, False, sourceFormat`. Для двух текстовых форматов передайте оба объекта. Сигнатуры и поведение прежних запросов с типизированными числами и текстом сохраняются.

Числовые даты — **серийные значения Excel**. Задайте `dateSystem="1900"` или `"1904"` по фактическому `Date1904` источника; если значение условия тоже числовая дата, настройте его отдельно. Преобразование учитывает сдвиг 1462 дня и ранние даты 1900; вымышленный день 60 отклоняется. Типизированные даты ADO/VBA уже календарные и не сдвигаются. Проекция сохраняет исходные числа, не переводя их автоматически в систему книги назначения. Пустые, Boolean и некорректные значения не приводятся к числам/датам.

Регрессионный скрипт охватывает запятую/точку, неправильные группы разрядов, разные форматы даты, високосные дни, невозможные и неоднозначные даты, системы 1900/1904, отсутствие и освобождение формата. Для исполнения VBA требуется разрешение; статическая проверка не заменяет runtime.

## Проверка

`WorkbookUpdater/Test-TableQueries.ps1` запускается на Windows с Excel, ACE и доверенным доступом к объектной модели VBA-проекта. Он создаёт и сохраняет временные книги, импортирует API в отдельную книгу запуска и выполняет одинаковые утверждения для обоих механизмов. Книги репозитория не меняются.

Проверяются типизированные фильтры, AND/OR, нормализация, регистр, буквальный поиск, сортировка, лимит, исключение итогов, пустой результат, адаптация к UI, диагностика отсутствующей колонки, живой Auto против сохранённого ADO, скалярные диапазоны, вызов через интерфейс, запрет работы до инициализации, повторной инициализации и инициализации после Dispose.

У конкретных API-классов есть Lifecycle и публичные Initialize/Dispose; интерфейсы содержат только контракт. Конструктор создаёт минимальное состояние, не вызывает публичный Initialize и не открывает ресурсы. Перед использованием явно вызовите Initialize и проверьте Boolean. Оба флага m_isInitialized и m_isDisposed сначала False. Успех ставит m_isInitialized=True; Dispose сбрасывает его и ставит m_isDisposed=True. Повторная инициализация живого или освобождённого экземпляра запрещена: для нового цикла создайте новый объект. Dispose повторяем, Class_Terminate вызывает Me.Dispose. DataTable.Initialize сохраняет аргументы схемы и данных.
