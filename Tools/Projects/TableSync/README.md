# TableSync

Соберите инструмент через `CompileTableSync.cmd` и запустите `build\TableSync.exe`. Он ищет `resources\TableSync.xml` относительно EXE. Из нескольких профилей выбирается отмеченный `default="true"`. Для разового запуска укажите путь к XML и имя профиля.

```xml
<profile name="Positions"
         tableDiff="..\..\TableDiff\build\TableDiff.exe">
    <books>
        <book name="source"
              file="ШПО.xlsx" />
        <book name="target"
              file="Рабочая.xlsx" />
    </books>
    <outputs directory="..\results\{DATE}">
        <previewReport file="Positions (preview).diff.html" />
        <appliedReport file="Positions (applied).diff.html" />
    </outputs>
    <source book="source"
            sheet="ОС"
            key="ІПН" />
    <update book="target"
            sheet="Список"
            key="ІПН">
        <field source="Посада"
               target="Посада" />
    </update>
</profile>
```

`book` ссылается на имя в `books`. `table` ограничивает диапазон именованной таблицей Excel. По умолчанию `rows="unique"` требует одну строку назначения на ключ в каждом действии. `rows="all"` обновляет все строки с этим ключом. Источник всегда должен содержать ровно одну запись на ключ. `compareIgnorePattern` на поле исключает совпавший текст при сравнении, запись берёт исходное значение.

Для встроенного сценария `match/fallback by="uniqueName"` позволяет указать таблицы поиска старого ключа через `search`.

Для специализированного сценария профиль содержит `<plugin assembly="…" />` вместо `source`, `update` и `match`. Путь к DLL считается от каталога XML. TableSync автоматически находит единственный публичный конкретный класс, реализующий `ISyncPlugin` из `TableSync.Contracts.dll`. Класс должен иметь публичный конструктор без аргументов. При отсутствии реализации или нескольких реализациях загрузка завершается ошибкой. Плагин получает снимки книг через `SyncContext.ReadTable` и возвращает `SyncPlan` с исходной книгой и группами правок. В `SyncEdit` номер строки соответствует Excel, индекс колонки начинается с нуля. Для добавления строк используйте снимок именованной таблицы и последовательные номера после `LastRow`. Группы с `Conflict` выводятся для ручной проверки и исключаются целиком.

Профиль `Personnel` загружает `TableSync.Plugins.Personnel.dll`. Плагин знает схему ШПО, РУХ и PeopleRegistry. Он группирует строки РУХ по ІПН и формирует связанные изменения, включая историю ключа. DLL запускается в процессе TableSync с правами пользователя, поэтому подключайте доверенные сборки.

Предпросмотр использует обычную таблицу diff: прежнее значение зачёркнуто, новое показано под ним в той же ячейке. Причины и номера строк источника доступны в раскрываемом блоке текущей вкладки. `SourceTable`, `SourceRow`, `SourceColumn` и `Reason` в `SyncEdit` описывают происхождение значения. Индекс `SourceColumn = -1` обозначает вычисленное действие по связанному изменению. `ConflictTables` привязывает конфликт к вкладкам назначения, а `DerivedConflict` обозначает конфликт вычисленного действия. После применения формируется обычный diff исходных и сохранённых книг.

Пути считаются от каталога XML. До подтверждения создаётся предварительный отчёт TableDiff. Введите `y` или `yes` для применения всего плана. Копии `(synced)` и оба отчёта сохраняются непосредственно в `outputs/@directory`, заменяя предыдущие результаты. Перед публикацией книги подготавливаются и проверяются во временном каталоге. Ошибка публикации запускает восстановление прежних результатов.
