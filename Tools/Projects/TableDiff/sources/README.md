# Сравнение книг Excel

`TableDiff` — перенос алгоритма и HTML-интерфейса из `C:/WORK/Windows/Строевые приказы/Tools/compare_excel.py` на C#. Сравниваются явно заданные пары листов двух сохранённых книг, включая листы с разными названиями. Результат — автономный `diff.html`, открываемый в браузере без сервера и интернета.

## Сборка и запуск

Нужна 64-разрядная Windows с .NET Framework 4.5 или новее для сборки через штатный `csc.exe`. Проекты Visual Studio настроены на .NET Framework 4.8. Для работы инструмента не нужны Python, .NET SDK или установленный Excel. Макросы не выполняются, исходные книги не изменяются.

Из каталога `Tools/Projects/TableDiff`:

```bat
CompileTableDiff.cmd
build\TableDiff.exe --help --no-pause
build\TableDiff.exe --validate --no-pause
build\TableDiff.exe --no-pause
build\TableDiff.exe --config TableDiff.Other.xml --no-pause
```

Сборка сначала создаёт общие DLL, затем EXE со встроенными CSS и JavaScript отчёта. Готовые файлы находятся в `build`, промежуточная `build/.staging` удаляется при завершении сборки. Развёртывайте EXE вместе с DLL из `build` и соседним каталогом `resources`.

## XML-конфигурация

Перед запуском настройте профили в `resources/TableDiff.xml`. Каждый профиль связывает конкретную упорядоченную пару файлов со своим отчётом и правилами сравнения листов. Текущий рабочий профиль `Movement` сохраняет ваши пути и ключ `УІД`. Ниже — пример двух профилей с относительными путями.

```xml
<?xml version="1.0" encoding="utf-8"?>
<tableDiff>
    <profiles>
        <profile name="Movement"
                 default="true"
                 output="../build/movement.{date}.diff.html">
            <old file="movement.old.xlsx" />
            <new file="movement.new.xlsx" />
            <comparisons>
                <comparison key="УІД"
                            threshold="0.65">
                    <old sheet="Список" />
                    <new sheet="Список" />
                </comparison>
                <comparison key="ПІБ"
                            threshold="0.80">
                    <old sheet="Відсутні" />
                    <new sheet="Відсутні" />
                </comparison>
            </comparisons>
        </profile>
        <profile name="Institutions"
                 output="../build/institutions.{date}.diff.html">
            <old file="institutions.old.xlsx" />
            <new file="institutions.new.xlsx" />
            <comparisons>
                <comparison key="Код"
                            threshold="0.85">
                    <old sheet="Установи" />
                    <new sheet="Довідник установ" />
                </comparison>
            </comparisons>
        </profile>
    </profiles>
</tableDiff>
```

- `profile/@name` — уникальное имя профиля. Имена сравниваются без учёта регистра.
- `profile/@default` — необязательный признак профиля по умолчанию: `true` или `false`. При отсутствии атрибута используется `false`. Только один профиль может иметь `default="true"`; несколько таких профилей считаются ошибкой конфигурации.
- `profile/old/@file` — старая версия; `profile/new/@file` — новая версия. Поддерживаются незашифрованные `.xlsx` и `.xlsm`.
- `profile/@output` — шаблон конечного пути HTML-отчёта этого профиля. Плейсхолдер `{date}` заменяется текущей локальной датой компьютера в формате `yyyy.MM.dd`: `../build/Movement.{date}.diff.html` → `../build/Movement.2026.11.05.diff.html`. Его можно поставить в любой части пути; без `{date}` имя остаётся как указано, дата автоматически не добавляется. Относительный путь отсчитывается от каталога XML. Каталог создаётся при необходимости. Повторный запуск с тем же конечным путём заменяет отчёт только после успешного формирования; отчёты с другими именами сохраняются.
- `profile/comparisons/comparison` — одна пара сравниваемых листов. Требуется хотя бы одна пара; порядок в XML определяет порядок разделов отчёта. Листы вне списка не читаются и не сравниваются.
- `comparison/old/@sheet` и `comparison/new/@sheet` — точные названия листов в старой и новой книге. Названия могут различаться. Регистр и пробелы значимы. Если лист отсутствует, выполнение останавливается с указанием книги и имени листа.
- `comparison/@key` — точное имя ключевого поля для распознавания заголовка и сопоставления записей внутри этой пары.
- `comparison/@threshold` — минимальная доля совпадений для этой пары: больше нуля и не больше единицы. Десятичный разделитель — точка. Ключ и порог обязательны в каждой паре; общих значений по умолчанию нет.

Одинаковая пара листов не может быть указана дважды внутри профиля. Один лист разрешается использовать в разных парах. Имена профилей и упорядоченные пары файлов должны быть уникальны. Старый формат без `profiles/profile` не поддерживается: перенесите пути книг, `output` и `comparisons` внутрь профиля, а ключ и порог — в каждый `comparison`.

## Выбор профиля

```bat
build\TableDiff.exe --profile Movement --no-pause
build\TableDiff.exe --profile Institutions --validate --no-pause
build\TableDiff.exe "C:\Reports\old.xlsx" "C:\Reports\new.xlsx" --no-pause
```

При передаче двух файлов профиль выбирается по точному совпадению нормализованных абсолютных путей без учёта регистра. Первый файл — старый, второй — новый; перестановка аргументов означает другую пару. Относительные пути из командной строки отсчитываются от текущего рабочего каталога, пути внутри XML — от каталога XML. Файлы не подменяют источники профиля: если соответствующего профиля нет, выполнение останавливается.

Если имя профиля и пара файлов не указаны, выбирается профиль с `default="true"`. Сейчас это `Movement`. Явный `--profile` или переданная пара файлов имеют приоритет над профилем по умолчанию. Если профиль единственный и признак не задан, сохраняется выбор единственного профиля. При нескольких профилях без признака по умолчанию нужно указать имя или два файла. Совмещать `--profile` с двумя файлами нельзя. Все описания профилей проверяются на корректность, но доступность входных книг проверяется только для выбранного профиля. Поэтому недоступный файл неиспользуемого профиля не мешает запуску другого.

Схема XML и пути выбранного профиля проверяются через `--validate`; наличие выбранных листов проверяется при чтении книг во время обычного запуска.

Все пути книг и отчёта разрешаются относительно XML. Имя конфигурации ищется рядом с EXE, затем в `resources` рядом с EXE, затем в `resources` родительского каталога. Явно заданный абсолютный или относительный путь с каталогами используется без поиска альтернатив. Ошибка найденной конфигурации не приводит к выбору другого файла.

`--validate` проверяет конфигурацию и пути без чтения содержимого книг. `--no-pause` отключает интерактивную паузу; перенаправление ввода также её отключает. Исключения записываются в `build/TableDiff.log`. Коды завершения: `0` — успех, `1` — ошибка. Наличие различий само по себе не является ошибкой.

## Правила сравнения

Книги читаются напрямую из ZIP/XML, без ADO и запуска Excel. Файл открывается только для чтения с разрешённым совместным доступом на чтение, запись и удаление, поэтому его можно сравнивать, пока он открыт в Excel. Учитывается сохранённая версия на диске; несохранённые изменения в Excel в сравнение не входят.

Алгоритм сохраняет правила Python-инструмента:

1. Пустые строки и ячейки только с оформлением не считаются записями. Сначала исключаются полностью одинаковые строки независимо от позиции и с учётом количества повторов.
2. Первая строка, содержащая точное значение `key`, считается заголовком. От ключевой колонки границы расширяются влево и вправо до первой пустой ячейки заголовка или края листа. Пустота означает пустую строку; пробелы считаются содержимым. Объединённые ячейки не расширяются автоматически. Только колонки этого непрерывного диапазона участвуют в точных совпадениях, расчёте близости и отчёте. Строки, пустые внутри диапазона, исключаются независимо от данных снаружи.
   Границы определяются независимо в обеих версиях. Колонки сопоставляются по точным названиям заголовков, поэтому сдвиг и перестановка колонок не считаются изменением данных. В отчёте сначала идут колонки новой версии, затем удалённые колонки в прежнем порядке. Добавленные заголовки отмечаются «+», удалённые — «−», даже если все их ячейки пусты. Переименование считается удалением прежней и добавлением новой колонки. При изменённой структуре повторяющиеся заголовки отклоняются как неоднозначные. В подсказках сохраняются реальные адреса каждой версии; у отсутствующей колонки адрес обозначается тире.
3. Оставшиеся строки ниже заголовка сопоставляются по одинаковому непустому ключу. Близость — доля равных полей среди общих колонок, заполненных хотя бы с одной стороны. Добавленные и удалённые колонки не снижают близость, но их непустые значения включаются в различия сопоставленной записи.
4. Выбирается кандидат с наибольшей близостью, затем ближайший по номеру строки, затем с большим индексом в новой книге. Равная близость двух лучших кандидатов отмечается как неоднозначность, даже если расстояния различаются.
5. Оставшиеся строки вне распознанной таблицы сопоставляются по номеру. Несопоставленные строки считаются удалёнными или добавленными.
6. Для каждого листа проверяется баланс: старые строки + добавленные − удалённые = новые строки.

Если заголовок найден только в одном из двух непустых листов пары, сравнение останавливается с ошибкой отсутствующего ключевого заголовка. Если второй лист существует, но пуст, строки найденного диапазона считаются добавленными или удалёнными. Если заголовок не найден ни на одном листе пары, сохраняется сравнение всего листа по прежней логике. Отсутствующий лист является ошибкой конфигурации пары. Правила границ строк по вертикали не изменены.

Сравниваются текстовые представления сохранённых значений и тексты формул, без пересчёта. Всегда читаются все сохранённые строки: фильтры листа и умных таблиц, вручную скрытые строки и столбцы не ограничивают сравнение. Сбрасывать фильтры в Excel или сохранять книги заново не требуется; инструмент не изменяет исходные файлы. Пустая ячейка и пустая строка эквивалентны. Регистр и пробелы значимы. Кэшированные результаты формул, оформление, макросы, примечания и скрытость строк не сравниваются.

Общая библиотека `Excel.OpenXml` читает ZIP/XML напрямую, включая общие строки, формулы, shared formulas и основные числовые форматы дат. Пути листов разрешаются через связи книги, а не предполагаемые имена `sheet1.xml`. Старый бинарный `.xls`, зашифрованные книги, Strict Open XML и листы-диаграммы не поддерживаются. Формулы таблиц подстановки (`dataTable`) отклоняются явно. Экзотические числовые форматы и формулы могут потребовать отдельного расширения; это не реализация вычислительного движка Excel.

## Отчёт

Результат отображается как плотная таблица с общей строкой заголовков и тонкой сеткой. Одна запись занимает одну строку; отдельные карточки и промежутки между ячейками отсутствуют. Верхняя панель содержит компактную сводку, поиск и фильтр. Заголовки колонок и служебные колонки статуса и номера строки закреплены при прокрутке.

Панель поиска, фильтра и чекбоксов постоянно видна у верхнего края окна и не смещается при вертикальной или горизонтальной прокрутке. Контент и заголовки таблицы учитывают текущую высоту панели. Непрозрачные служебные колонки начинаются от левого края окна без просвечивающего зазора.

Справа в закреплённой панели находятся кнопки ↑ и ↓: переход к началу и концу таблицы текущей страницы. Они сохраняют горизонтальную позицию прокрутки и учитывают высоту верхней панели и нижних вкладок.

На странице отображается не больше 100 записей выбранной пары листов. Кнопки над таблицей переходят на первую, предыдущую, следующую и последнюю страницу; рядом указаны диапазон записей и номер страницы. Поиск и фильтры обрабатывают все различия выбранной пары, а не только видимую страницу. После изменения поиска или фильтра вывод начинается с первой страницы результатов.

В HTML встроены компактные данные: повторяющиеся значения хранятся один раз в словаре, а строки ссылаются на них по индексам. Данные листа разбираются при первом выборе его вкладки. Таблица создаётся только для активной вкладки; при переключении прежняя разметка удаляется. Файл остаётся автономным: сервер, интернет и повторное чтение Excel при просмотре не нужны. Печать через браузер выводит текущую страницу таблицы.

Текст переносится внутри заданной ширины колонки. Каждое значение ограничено тремя видимыми строками с многоточием при превышении. Лимиты независимы: максимум три строки старого и три строки нового. Если старое занимает одну строку, новое всё равно ограничивается тремя. Учитываются явные переводы строк и переносы по ширине колонки; при изменении ширины ограничение пересчитывается автоматически. Полный текст остаётся в отчёте и участвует в поиске. Старое значение зачёркнуто, новое расположено ниже. Зелёный фон означает добавление, фиолетовый — замену, красный — удаление. Обычные неизменённые значения также видны; пустые ячейки отмечаются тире.

Неизменённые формулы по умолчанию показаны компактной отметкой «= без изменений», чтобы длинные служебные формулы не увеличивали высоту каждой строки. Переключатель «Неизменённые формулы» показывает их текст с тем же ограничением в три строки. Ограничение также применяется к изменённым формулам и формулам в добавленных или удалённых записях.

Чекбокс «Скрывать неизменённые колонки» сворачивает соседние колонки, значения которых не менялись ни в одной записи текущей страницы, в одну узкую колонку шириной 24 px с «…». Подсказка перечисляет скрытые названия и их количество. Группы пересчитываются при переходе на другую страницу, поиске и фильтрации; колонка с изменением хотя бы в одной видимой записи остаётся открытой. Заполненные поля добавленных и удалённых записей считаются изменёнными. Скрытие не влияет на сравнение и поиск по полным данным. При отключении чекбокса все колонки восстанавливаются с сохранёнными ширинами.

Служебная колонка «Строка» показывает старый и новый номера; одинаковые номера выводятся один раз. При неоднозначном сопоставлении рядом со статусом стоит знак «?» с пояснением. Подсказка ячейки содержит её исходные адреса в обеих версиях. Пользовательские значения экранируются перед вставкой в HTML.

Поиск учитывает полные старые и новые значения, а также названия изменённых полей. Он запускается через 200 мс после ввода и использует кэш текста записей; обработка больших наборов выполняется порциями, чтобы браузер мог реагировать на действия пользователя. Устаревший поиск отменяется при новом вводе или переключении вкладки. Фильтр ограничивает строки по типу изменения. Если подходящих строк нет, выводится сообщение. Каждая пара листов имеет отдельную вкладку; разные названия отображаются как «старый лист → новый лист». Сводка показывает оба названия, ключ и порог.

Ширина меняется перетаскиванием правой границы колонки по всей высоте таблицы, включая заголовок и любую строку данных. При наведении граница подсвечивается и становится толще, появляется курсор изменения ширины; диапазон — 60–600 px. Во время перетаскивания движется только направляющая линия; ширина колонки применяется после отпускания мыши, без постоянного пересчёта всех переносов. Активные границы пересчитываются при прокрутке, фильтрации, переключении листов и изменении высоты строк. Колонка и её заголовок меняются одновременно, переносы и ограничение в три строки пересчитываются автоматически. Ширины сохраняются между страницами и вкладками. Двойной щелчок по границе возвращает 170 px. Граница доступна с клавиатуры: стрелки меняют ширину на 10 px, Shift со стрелкой — на 50 px, Home/End задают минимум/максимум. Escape отменяет активное перетаскивание.

Нижняя панель ползунков удалена, внизу остаются только вкладки листов. Размеры автоматически сохраняются в браузере; прежние настройки совместимы. Кнопка «Сбросить ширины» находится рядом с фильтрами: появляется после изменения ширины на текущем листе, в том числе при восстановлении сохранённых настроек, и скрывается после сброса. Она возвращает все колонки текущего листа к 170 px при масштабе 100% и удаляет его сохранённые настройки. Импорт/экспорт `excel-column-widths.json` находятся в раскрывающейся сводке сверху. Доступность сохранения зависит от настроек браузера для локальных HTML-файлов.

Справа в верхней панели рядом с кнопками ↑/↓ расположен ползунок «Ширина»: 55–190% с шагом 15 процентных пунктов, при открытии отчёта — 100%. Доступные значения: 55, 70, 85, 100, 115, 130, 145, 160, 175 и 190%. Он пропорционально меняет ширины всех колонок данных на всех листах, сохраняя их индивидуальные пропорции. Например, 170 и 240 px при 55% становятся 93,5 и 132 px. Размер шрифта, служебные колонки и группы «…» не меняются. Ручные размеры сохраняются и экспортируются в пересчёте на 100%; масштаб действует только до перезагрузки отчёта. Сброс ширин сохраняет выбранный масштаб.

## Организация кода

Чекбокс «Изменять ширину сразу» в верхней панели переключает режимы прямо в открытом отчёте. По умолчанию он включён: ширина и переносы меняются во время движения мыши. При отключении движется только направляющая, ширина применяется после отпускания мыши. Escape в обоих режимах отменяет изменение. Переключение режима во время перетаскивания отменяет текущую операцию; перезагрузка страницы для смены режима не требуется.

- `common/Excel.Tables` — снимки книг, листов и строк, адреса столбцов.
- `common/Excel.OpenXml` — чтение сохранённых значений и формул без COM.
- `common/Tooling` и `common/Tooling.Console` — поиск конфигурации, публикация отчёта, журналирование и консольный запуск.
- `Configuration`, `Comparison`, `Reporting` — специфические части инструмента.

Новые тестовые файлы при переносе не создавались.
