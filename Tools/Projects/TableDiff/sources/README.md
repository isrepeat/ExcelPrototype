# Сравнение книг Excel

`TableDiff` — перенос алгоритма и HTML-интерфейса из `C:/WORK/Windows/Строевые приказы/Tools/compare_excel.py` на C#. Сравниваются явно заданные пары листов двух сохранённых книг, включая листы с разными названиями. Результат — автономный `diff.html`, открываемый в браузере без сервера и интернета.

## Сборка и запуск

Нужна 64-разрядная Windows с .NET Framework 4.5 или новее для сборки через штатный `csc.exe`. Проекты Visual Studio настроены на .NET Framework 4.8. Для работы инструмента не нужны Python, .NET SDK или установленный Excel. Макросы не выполняются, исходные книги не изменяются.

Из каталога `Tools/Projects/TableDiff`:

```bat
CompileTableDiff.cmd
build\TableDiff.exe --help --no-pause
build\TableDiff.exe --validate --no-pause
build\TableDiff.exe --no-pause
build\TableDiff.exe --config TableDiff.Other.xml --no-pause
```

Сборка сначала создаёт общие DLL, затем EXE со встроенными CSS и JavaScript отчёта. Готовые файлы находятся в `build`, промежуточная `build/.staging` удаляется при завершении сборки. Развёртывайте EXE вместе с DLL из `build` и соседним каталогом `resources`.

## XML-конфигурация

Перед запуском настройте профили в `resources/TableDiff.xml`. Каждый профиль связывает конкретную упорядоченную пару файлов со своим отчётом и правилами сравнения листов. Текущий рабочий профиль `Movement` сохраняет ваши пути и ключ `УІД`. Ниже — пример двух профилей с относительными путями.

```xml
<?xml version="1.0" encoding="utf-8"?>
<tableDiff>
    <profiles>
        <profile name="Movement"
                 output="../build/movement.diff.html">
            <old file="movement.old.xlsx" />
            <new file="movement.new.xlsx" />
            <comparisons>
                <comparison key="УІД"
                            threshold="0.65">
                    <old sheet="Список" />
                    <new sheet="Список" />
                </comparison>
                <comparison key="ПІБ"
                            threshold="0.80">
                    <old sheet="Відсутні" />
                    <new sheet="Відсутні" />
                </comparison>
            </comparisons>
        </profile>
        <profile name="Institutions"
                 output="../build/institutions.diff.html">
            <old file="institutions.old.xlsx" />
            <new file="institutions.new.xlsx" />
            <comparisons>
                <comparison key="Код"
                            threshold="0.85">
                    <old sheet="Установи" />
                    <new sheet="Довідник установ" />
                </comparison>
            </comparisons>
        </profile>
    </profiles>
</tableDiff>
```

- `profile/@name` — уникальное имя профиля. Имена сравниваются без учёта регистра.
- `profile/old/@file` — старая версия; `profile/new/@file` — новая версия. Поддерживаются незашифрованные `.xlsx` и `.xlsm`.
- `profile/@output` — HTML-отчёт этого профиля. Каталог создаётся при необходимости, прежний отчёт заменяется после успешного сравнения и формирования нового файла.
- `profile/comparisons/comparison` — одна пара сравниваемых листов. Требуется хотя бы одна пара; порядок в XML определяет порядок разделов отчёта. Листы вне списка не читаются и не сравниваются.
- `comparison/old/@sheet` и `comparison/new/@sheet` — точные названия листов в старой и новой книге. Названия могут различаться. Регистр и пробелы значимы. Если лист отсутствует, выполнение останавливается с указанием книги и имени листа.
- `comparison/@key` — точное имя ключевого поля для распознавания заголовка и сопоставления записей внутри этой пары.
- `comparison/@threshold` — минимальная доля совпадений для этой пары: больше нуля и не больше единицы. Десятичный разделитель — точка. Ключ и порог обязательны в каждой паре; общих значений по умолчанию нет.

Одинаковая пара листов не может быть указана дважды внутри профиля. Один лист разрешается использовать в разных парах. Имена профилей и упорядоченные пары файлов должны быть уникальны. Старый формат без `profiles/profile` не поддерживается: перенесите пути книг, `output` и `comparisons` внутрь профиля, а ключ и порог — в каждый `comparison`.

## Выбор профиля

```bat
build\TableDiff.exe --profile Movement --no-pause
build\TableDiff.exe --profile Institutions --validate --no-pause
build\TableDiff.exe "C:\Reports\old.xlsx" "C:\Reports\new.xlsx" --no-pause
```

При передаче двух файлов профиль выбирается по точному совпадению нормализованных абсолютных путей без учёта регистра. Первый файл — старый, второй — новый; перестановка аргументов означает другую пару. Относительные пути из командной строки отсчитываются от текущего рабочего каталога, пути внутри XML — от каталога XML. Файлы не подменяют источники профиля: если соответствующего профиля нет, выполнение останавливается.

Если профиль единственный, его можно запускать без `--profile`. При нескольких профилях выбор обязателен: имя или два файла. Совмещать `--profile` с двумя файлами нельзя. Все описания профилей проверяются на корректность, но доступность входных книг проверяется только для выбранного профиля. Поэтому недоступный файл неиспользуемого профиля не мешает запуску другого.

Схема XML и пути выбранного профиля проверяются через `--validate`; наличие выбранных листов проверяется при чтении книг во время обычного запуска.

Все пути книг и отчёта разрешаются относительно XML. Имя конфигурации ищется рядом с EXE, затем в `resources` рядом с EXE, затем в `resources` родительского каталога. Явно заданный абсолютный или относительный путь с каталогами используется без поиска альтернатив. Ошибка найденной конфигурации не приводит к выбору другого файла.

`--validate` проверяет конфигурацию и пути без чтения содержимого книг. `--no-pause` отключает интерактивную паузу; перенаправление ввода также её отключает. Исключения записываются в `build/TableDiff.log`. Коды завершения: `0` — успех, `1` — ошибка. Наличие различий само по себе не является ошибкой.

## Правила сравнения

Алгоритм сохраняет правила Python-инструмента:

1. Пустые строки и ячейки только с оформлением не считаются записями. Сначала исключаются полностью одинаковые строки независимо от позиции и с учётом количества повторов.
2. Первая строка, содержащая точное значение `key`, считается заголовком. От ключевой колонки границы расширяются влево и вправо до первой пустой ячейки заголовка или края листа. Пустота означает пустую строку; пробелы считаются содержимым. Объединённые ячейки не расширяются автоматически. Только колонки этого непрерывного диапазона участвуют в точных совпадениях, расчёте близости и отчёте. Строки, пустые внутри диапазона, исключаются независимо от данных снаружи.
   Границы определяются независимо в обеих версиях. Одинаковые последовательности заголовков сравниваются относительно начала своих диапазонов: горизонтальный сдвиг таблицы не считается изменением. В отчёте сохраняются реальные адреса ячеек каждой версии. Если состав или порядок заголовков различается, сравнение останавливается: добавленные, удалённые и переставленные колонки пока автоматически не сопоставляются.
3. Оставшиеся строки ниже заголовка сопоставляются по одинаковому непустому ключу. Близость — доля равных полей среди тех, которые заполнены хотя бы с одной стороны.
4. Выбирается кандидат с наибольшей близостью, затем ближайший по номеру строки, затем с большим индексом в новой книге. Равная близость двух лучших кандидатов отмечается как неоднозначность, даже если расстояния различаются.
5. Оставшиеся строки вне распознанной таблицы сопоставляются по номеру. Несопоставленные строки считаются удалёнными или добавленными.
6. Для каждого листа проверяется баланс: старые строки + добавленные − удалённые = новые строки.

Если заголовок найден только в одном из двух непустых листов пары, сравнение останавливается с ошибкой отсутствующего ключевого заголовка. Если второй лист существует, но пуст, строки найденного диапазона считаются добавленными или удалёнными. Если заголовок не найден ни на одном листе пары, сохраняется сравнение всего листа по прежней логике. Отсутствующий лист является ошибкой конфигурации пары. Правила границ строк по вертикали не изменены.

Сравниваются текстовые представления сохранённых значений и тексты формул, без пересчёта. Всегда читаются все сохранённые строки: фильтры листа и умных таблиц, вручную скрытые строки и столбцы не ограничивают сравнение. Сбрасывать фильтры в Excel или сохранять книги заново не требуется; инструмент не изменяет исходные файлы. Пустая ячейка и пустая строка эквивалентны. Регистр и пробелы значимы. Кэшированные результаты формул, оформление, макросы, примечания и скрытость строк не сравниваются.

Общая библиотека `Excel.OpenXml` читает ZIP/XML напрямую, включая общие строки, формулы, shared formulas и основные числовые форматы дат. Пути листов разрешаются через связи книги, а не предполагаемые имена `sheet1.xml`. Старый бинарный `.xls`, зашифрованные книги, Strict Open XML и листы-диаграммы не поддерживаются. Формулы таблиц подстановки (`dataTable`) отклоняются явно. Экзотические числовые форматы и формулы могут потребовать отдельного расширения; это не реализация вычислительного движка Excel.

## Отчёт

Сохранены тёмная тема, горизонтальные карточки столбцов, цвета добавления/замены/удаления, значения «Было», поиск и фильтр изменений. Нажатие на ячейку открывает полное содержимое. Одинаковые ячейки показаны как `-- // --`, их исходное значение доступно в диалоге. Длинные тексты и формулы можно раскрыть.

Каждая пара имеет отдельную вкладку; для разных названий отображается «старый лист → новый лист». Сводка показывает оба названия, ключ и порог каждой пары. Панель ширин сохраняет размеры в браузере; доступны импорт и экспорт `excel-column-widths.json`. Доступность сохранения зависит от настроек браузера для локальных HTML-файлов. При сравнении пользовательские значения экранируются перед вставкой в HTML.

## Организация кода

- `common/Excel.Tables` — снимки книг, листов и строк, адреса столбцов.
- `common/Excel.OpenXml` — чтение сохранённых значений и формул без COM.
- `common/Tooling` и `common/Tooling.Console` — поиск конфигурации, публикация отчёта, журналирование и консольный запуск.
- `Configuration`, `Comparison`, `Reporting` — специфические части инструмента.

Новые тестовые файлы при переносе не создавались.
